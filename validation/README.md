# Reproducible validation

This directory retains the **necessary scientific evidence without internal research campaign logs**. It separates executable synthetic R-reference tests, aggregate retrospective case findings and historical performance data.

## Reproduce stored-R compatibility

Install the package and its tested extras in a clean environment; do not import an editable working copy while claiming to test an artifact.

```bash
(cd validation/golden && sha256sum -c SHA256SUMS)
python validation/tools/run_parity_suite.py \
  --repo-root . --oracle-root validation/golden \
  --out-dir validation/generated/parity
```

The expected reference suite contains 47 checks and six detecting negative controls. The relocated runner preserves the original numerical comparisons and now exits nonzero for failed checks or missing expected controls. Its thresholds are module-specific, not one blanket equality promise. Stored outputs were generated by real R runs, but executing this Python runner does not regenerate R.

[Reference profiles and hashes](golden/PROVENANCE.json) · [Golden files](golden) · [Comparator](tools/compare_labelled.py)

The reference inputs are synthetic: a small programmatic Seurat cohort and explicit LMC edge cases. No human raw/processed expression matrices are bundled. Session logs and private filesystem paths are excluded. Actual R export scripts are retained under [r_reference](r_reference); recreate the declared isolated R environment before attempting a fresh export, and use new output paths rather than overwriting the saved goldens.

## Core package and portable example

```bash
python -m pytest -q tests
python -m pytest -q validation/tools/test_compare_labelled.py
python examples/r_to_python_migration_quickstart.py --out-dir ./scslide-demo-output
```

The approved 0.3.3 artifact has historical direct evidence for 43 distinct package tests, separately from helper tests. CI additionally validates installed builds outside the checkout. New test execution is recorded by the workflow, not inferred from these historical counts.

## Software identity

The exact artifact checksums are in [artifacts](../artifacts/manifest.json). A clean software export verifies that numerical source and package tests remain byte-identical, while documentation, validation paths and CI are relocated. Generated hashes and export checks are in `PUBLIC_SNAPSHOT_MANIFEST.json`. Source-tree builds after documentation changes are distinct packaging files from the preserved audited ZIPs.

A successful reference test does not establish clinical validity or general post-selection FDR. Exploratory inference remains explicitly marked in the public API and scientific usage documentation.
